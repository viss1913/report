# Partner Guide — как править шаблоны отчётов

## Зачем этот репозиторий

Партнёр (Финам, Ростех, Ренессанс и др.) получает **чистую вёрстку** отчёта без backend-кода.

Типичный сценарий:

1. Дизайнер / маркетинг хочет другой цвет, лого, формулировку.
2. Партнёр открывает этот репо в Cursor / Claude.
3. Агент правит HTML/CSS.
4. Партнёр пушит ветку → PFP прикручивает к PDF-генерации.

## Выбор бренда

| Нужно поправить | Папка |
|-----------------|-------|
| Отчёт Финам v2 | `brands/finam-v2/` |
| Отчёт Ростех НПФ | `brands/rostech/` |
| Отчёт Ренессанс / YADRO ПДС | `brands/renaissance/` |

Не смешивайте бренды в одном PR.

## Геометрия страницы

Все бренды проектируются под холст:

- ширина **595px**
- высота **842px**
- это CSS-эквивалент A4 при 72dpi-логике макета

Production PDF масштабирует страницу ×4/3 (до ~794×1123).  
Если контент вылезает за 595×842 в HTML — в PDF обрежется.

## Ассеты

- Кладите файлы в `brands/<brand>/assets/`
- В HTML используйте относительные пути: `assets/logo.svg`
- Не используйте абсолютные `file://` и внешние CDN для критичных картинок (кроме Google Fonts, если уже есть в шаблоне)
- Имена без `%`, пробелов по возможности; если пробелы уже есть — не ломайте существующие ссылки

## Данные клиента vs статичный текст

| Тип | Пример | Можно менять? |
|-----|--------|----------------|
| Статичный маркетинг | «Персональный финансовый план» | да |
| Data-field Finam | `data-finam-v2-field="reserve-initial"` | class/CSS — да; имя field — нет |
| Placeholder | `{{monthly_contribution}}` | имя — нет; вокруг — да |
| Демо-сумма внутри field | `300 000 ₽` | можно оставить как мок; в prod заменится |

## Как сдать правки

```bash
git checkout -b partner/finam-v2-new-cover
# ... edits ...
node scripts/check-templates.js
git add brands/finam-v2
git commit -m "finam-v2: update cover branding"
git push -u origin HEAD
```

Откройте Pull Request в https://github.com/viss1913/report

В описании PR укажите:

- какой бренд;
- что изменилось визуально (3–7 пунктов);
- скриншоты до/после (желательно).

## Что делает команда PFP после merge

1. Копирует файлы в backend PFP.
2. Сверяет applier/loader с манифестом.
3. Генерирует тестовый PDF на реальном клиенте.
4. Выкатывает на project партнёра.

## Частые ошибки

1. **Удалили `data-finam-v2-field`** — сумма в PDF останется демо или пропадёт блок.
2. **Переименовали `{{client_name}}` → `{{name}}`** — бэкенд не знает новый ключ.
3. **Сделали страницу 800px высотой** — обрезание в Puppeteer.
4. **Положили лого через base64 прямо в HTML на 5MB** — раздувает PDF; лучше файл в `assets/`.
5. **Правили сразу Finam и Rostech** — сложный review, долгий merge.

## Юридическое

Тексты дисклеймеров / декларации рисков меняйте осознанно.  
Если сомневаетесь — правьте только визуал и оставьте юридический текст как был.
